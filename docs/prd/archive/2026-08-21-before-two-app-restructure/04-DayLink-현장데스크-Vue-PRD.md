# PRD 04 — DayLink 현장 데스크

- 제품명: DayLink Desk
- 기술: Vue + TypeScript + Vite 기반 SPA/PWA
- 문서 버전: 1.0
- 우선순위 표기: P0 필수, P1 후속, P2 학습 확장
- 공통 정책: `00-DayLink-PRD-개요.md`를 따른다.

## 1. 제품 요약

파트너 현장 직원이 태블릿이나 휴대전화에서 당일 회차와 참석자를 확인하고 QR로 체크인하는 설치형 웹 앱이다. 통신이 불안정한 장소를 가정해 최소 참석자 자료를 미리 내려받고, 오프라인 체크인을 큐에 저장한 뒤 재연결 시 안전하게 동기화한다.

Vue 자체의 반응성, 컴포넌트 통신, 내장 컴포넌트, 라우터, Pinia, 장치 API, PWA·오프라인 상태를 집중 학습한다.

## 2. 목표와 제외 범위

### 2.1 목표

- 현장 직원이 3번 이하의 동작으로 예약 QR을 판독하고 결과를 안다.
- 통신이 끊겨도 미리 동기화된 당일 예약은 체크인할 수 있다.
- 두 장치의 중복 체크인을 서버가 일관된 결과로 병합한다.
- 개인정보를 최소한만 캐시하고 교대 종료·권한 회수 때 삭제한다.
- 카메라 거부, 손상 QR, 미동기화 예약, 장치 시간 오류를 명확히 처리한다.
- Vue의 Composition API와 내장 컴포넌트를 실제 장치·오프라인 요구에 연결한다.

### 2.2 제외 범위

- 오프라인 신규 예약·현장 결제
- 실제 출입문·프린터·NFC 하드웨어 제어
- 고객 연락처 전체 내려받기
- 현장 직원의 취소·환불·가격 변경
- 미리 동기화되지 않은 예약의 오프라인 임의 승인

## 3. 사용자와 권한

| 역할 | 할 수 있는 일 | 제한 |
|---|---|---|
| 현장 직원 | 지정 사업장의 당일 회차·최소 참석자 조회, 체크인, 사고 초안 | 환불, 정원·상품 수정, 타 사업장 조회 불가 |
| 현장 슈퍼바이저 | 직원 기능 + 온라인 체크인 정정, 사고 제출, 장치 해제 요청 | 결제·정산·팀 역할 변경 불가 |
| 매니저 | 여러 사업장 전환, 동기화 상태 확인 | 파트너센터 고유 권한은 별도 세션에서 수행 |

장치 등록과 사용자 로그인을 모두 요구한다. 권한이 회수되면 다음 온라인 요청에서 세션을 종료하고 로컬 캐시를 삭제한다.

## 4. 성공 지표

| 지표 | 정의 |
|---|---|
| QR 판독→결과 시간 | 카메라 인식부터 결과 표시까지 걸린 시간 |
| 정상 체크인 성공률 | 유효 QR 중 추가 조치 없이 완료된 비율 |
| 오프라인 동기화 성공률 | 큐 이벤트 중 자동으로 서버 반영된 비율 |
| 충돌 수동 처리율 | 자동 병합하지 못하고 슈퍼바이저가 개입한 비율 |
| 미동기화 예약 차단률 | 오프라인에서 권한 없이 임의 승인하지 않고 차단한 비율 |
| 개인정보 잔존 위반 | 만료·로그아웃 뒤 캐시가 남은 건수, 목표 0 |
| 카메라 불가 대체 완료율 | 수동 코드·검색으로 체크인을 완료한 비율 |

## 5. 정보 구조

| 경로 | 화면 | 접근 |
|---|---|---|
| `/login` | 직원 로그인 | 공개 |
| `/device/register` | 장치 등록 | 로그인 |
| `/venues` | 사업장 선택 | 복수 사업장 사용자 |
| `/today` | 오늘의 현장 대시보드 | 지정 직원 |
| `/sessions/:sessionId` | 회차·참석자 | 지정 직원 |
| `/scan/:sessionId?` | QR 스캐너 | 지정 직원 |
| `/manual-checkin` | 수동 조회 | 온라인 기본 |
| `/sync` | 오프라인 큐·충돌 | 지정 직원 |
| `/incidents/new` | 사고 기록 | 지정 직원 |
| `/incidents/:id` | 사고 상세 | 권한별 |
| `/settings` | 카메라·저장소·네트워크 진단 | 로그인 |

`오늘`, `회차`, `스캔` 탭은 이동 중 상태를 보존한다. 민감정보 화면은 백그라운드 전환 뒤 지정 시간이 지나면 가린다.

## 6. 체크인 도메인 규칙

### 6.1 참석 상태

| 상태 | 의미 |
|---|---|
| `NOT_CHECKED_IN` | 예약 인원 중 체크인 0명 |
| `PARTIAL` | 일부 인원만 체크인 |
| `COMPLETE` | 예약 인원 전부 체크인 |
| `NO_SHOW` | 회차 마감 후 체크인 0명 |
| `CORRECTED` | 슈퍼바이저가 사유와 함께 정정 |

한 예약이 4명이라면 2명을 먼저 체크인하고 나머지 2명을 나중에 처리할 수 있다. 누적 체크인 인원은 예약 인원을 초과할 수 없다.

### 6.2 QR

- QR에는 불투명한 참석 토큰만 담는다.
- 토큰에서 이름, 전화번호, 예약번호를 유추할 수 없어야 한다.
- 온라인에서는 Core API가 토큰, 사업장, 회차, 예약 상태를 검증한다.
- 오프라인에서는 마지막으로 동기화한 허용 토큰 해시 목록과 비교한다.
- 동기화되지 않은 토큰은 오프라인에서 승인하지 않는다.

### 6.3 체크인 이벤트

각 체크인 이벤트는 다음을 포함한다.

- clientEventId(UUID, 멱등 키)
- bookingId 또는 토큰으로 해석된 내부 참조
- sessionId, venueId
- checkInCount
- deviceId, actorId
- clientRecordedAt, serverReceivedAt
- online/offline 출처
- cacheSnapshotVersion

장치 시각은 증거로 남기되 공식 처리 순서와 정책 판단은 서버 시각을 사용한다.

## 7. 기능 요구사항

### 7.1 로그인·장치 등록

#### DESK-AUTH-001 [P0] 로그인

- 파트너센터와 별도 현장용 세션을 사용한다.
- 로그인 뒤 오늘 배정된 사업장과 역할을 조회한다.
- 배정이 없으면 데이터 없이 관리자 문의 경로를 보여준다.

#### DESK-DEV-001 [P0] 장치 등록

- 장치 별칭, 사업장 범위, 등록자, 만료 시각을 기록한다.
- 공유 태블릿은 교대마다 직원이 다시 로그인한다.
- 장치 해제 시 다음 온라인 연결에서 세션·캐시를 폐기한다.

#### DESK-DEV-002 [P0] 권한·환경 진단

- 카메라, 저장소 사용 가능량, service worker, 네트워크, 마지막 동기화 시각을 표시한다.
- 카메라 권한이 거부된 경우 브라우저 설정 안내와 수동 입력을 제공한다.
- HTTPS가 아니어서 카메라·PWA가 불가능하면 원인을 명시한다.

### 7.2 오늘의 운영

#### DESK-TDY-001 [P0] 오늘 회차

- 현재 사업장의 오늘 회차를 시작 시각 순으로 표시한다.
- 상태, 예약 인원, 체크인 인원, 남은 인원, 동기화 상태를 보여준다.
- 과거·진행 중·예정 회차를 시각과 텍스트로 구분한다.

#### DESK-TDY-002 [P0] 사전 동기화

- 앱 시작, 사업장 선택, 수동 새로고침 때 당일 회차와 최소 참석자 스냅샷을 받는다.
- 받아온 snapshotVersion과 만료 시각을 표시한다.
- 로컬 미전송 이벤트를 먼저 서버에 반영한 뒤 새 스냅샷을 교체한다.
- 동기화 실패 시 기존 스냅샷을 유지하고 오래된 정도를 명시한다.
- 온라인이면 회차 시작 30분 전 새 스냅샷을 반드시 시도한다.
- 마지막 성공 스냅샷이 2시간을 넘으면 오프라인 체크인을 승인하지 않는다.

#### DESK-TDY-003 [P1] 교대 시작 체크리스트

- 카메라, 네트워크, 동기화, 배터리 권한 안내, 비상 연락 경로를 확인한다.
- 경고가 있어도 가능한 기능과 불가능한 기능을 나눠 알려준다.

### 7.3 회차·참석자

#### DESK-SES-001 [P0] 회차 상세

- 상품명, 시각, 장소, 예약·체크인 합계, 운영 공지, 참석자 목록을 표시한다.
- 참석자는 마스킹 이름, 예약 인원, 체크인 인원, 예약번호 뒷자리만 기본 제공한다.
- 취소·환불된 예약은 체크인할 수 없고 이유를 표시한다.

#### DESK-SES-002 [P0] 참석자 필터

- 미체크인, 일부 체크인, 완료, 문제 건으로 필터링한다.
- 검색은 온라인에서 예약번호·전화번호 뒷자리를 지원하고 오프라인에서는 캐시된 최소 필드만 사용한다.
- 0건과 검색 실패를 구분한다.

### 7.4 QR 체크인

#### DESK-SCN-001 [P0] 스캐너

- 카메라 시작 전 권한 이유를 설명한다.
- 인식 성공 뒤 같은 프레임의 반복 판독을 잠시 잠근다.
- 판독, 검증 중, 성공, 일부 성공, 이미 완료, 잘못된 QR, 다른 회차, 취소 예약을 서로 다른 결과로 표시하고 음향·진동은 설정에 따른다.

#### DESK-SCN-002 [P0] 인원 확인

- 예약 인원과 기존 체크인 인원을 보여주고 이번 체크인 인원을 선택한다.
- 기본값은 남은 인원이지만 직원이 줄일 수 있다.
- 0명 또는 남은 인원 초과를 보낼 수 없다.

#### DESK-SCN-003 [P0] 온라인 체크인

- clientEventId와 함께 Core API에 요청한다.
- 서버 성공 후 공식 누적 인원과 상태를 표시한다.
- 네트워크 응답이 사라지면 같은 clientEventId로 상태를 조회하거나 재전송한다.
- 타임아웃을 실패 확정으로 간주해 새 이벤트를 만들지 않는다.

#### DESK-SCN-004 [P0] 오프라인 체크인

- 유효한 최신 캐시 토큰인 경우 로컬 큐에 이벤트를 저장하고 `동기화 대기`임을 명확히 표시한다.
- 로컬 예상 인원을 갱신하되 공식 서버 확인 전 표시를 구분한다.
- 토큰이 캐시에 없거나 스냅샷이 만료 기준을 넘으면 승인하지 않고 온라인 확인을 요구한다.

#### DESK-SCN-005 [P0] 중복·충돌

- 온라인에서 이미 체크인된 이벤트는 현재 공식 상태를 성공성 결과로 표시한다.
- 두 오프라인 장치가 같은 인원을 체크인한 경우 서버가 먼저 반영된 이벤트까지만 인정한다.
- 뒤 이벤트는 `ALREADY_CHECKED_IN` 또는 `COUNT_EXCEEDED`로 반환하고 공식 인원으로 UI를 교정한다.
- 자동 교정되지 않는 회차·예약 불일치는 충돌 큐로 보낸다.

#### DESK-SCN-006 [P0] 대체 입력

- 카메라 불가 시 짧은 수동 확인 코드 또는 온라인 예약 검색을 제공한다.
- 순차 예약 ID 전체를 QR 대체 코드로 사용하지 않는다.
- 반복 실패와 무차별 대입은 속도 제한한다.

### 7.5 동기화

#### DESK-SYNC-001 [P0] 오프라인 큐

- 대기, 전송 중, 성공, 자동 병합, 확인 필요 상태를 보여준다.
- 큐는 생성 순서를 보존하지만 서로 다른 예약은 제한된 병렬 전송을 허용한다.
- 재시도마다 같은 clientEventId를 사용한다.

#### DESK-SYNC-002 [P0] 재연결

- 브라우저 online 이벤트만 믿지 않고 실제 health check 성공 뒤 동기화를 시작한다.
- 미전송 이벤트→서버 결과 반영→새 스냅샷 순으로 처리한다.
- 앱을 닫았다 다시 열어도 큐가 복원된다.

#### DESK-SYNC-003 [P0] 충돌 처리

- 자동 병합 가능한 중복은 공식 상태로 닫는다.
- 다른 회차, 취소 후 오프라인 체크인, 권한 회수는 직원이 강제 승인할 수 없다.
- 슈퍼바이저는 온라인에서 사건을 확인하고 정정 또는 무효 처리하며 사유를 남긴다.

#### DESK-SYNC-004 [P0] 캐시 수명

- 당일 운영 종료 후 지정 시간에 참석자 캐시를 제거한다.
- 로그아웃, 장치 해제, 역할 회수 시 즉시 제거한다.
- 미전송 이벤트가 있으면 로그아웃 전에 전송을 시도한다. 실패해도 로그아웃을 막지는 않는다.
- 로그아웃 뒤 참석자 캐시는 제거하되 이름·연락처가 없는 서명된 이벤트 큐는 잠그고 다음 권한자의 동기화 또는 관리자 인계 때까지 보존한다.
- 역할이 회수된 이벤트는 공식 참석으로 강제 반영하지 않고 서버 격리 큐에서 원래 actor·device와 함께 검토한다.

### 7.6 수동 정정·사고

#### DESK-COR-001 [P0] 체크인 정정

- 서버에 반영된 체크인 취소·인원 감소는 온라인 슈퍼바이저만 할 수 있다.
- 대상, 현재 상태, 변경 값, 필수 사유, 재인증을 요구한다.
- 기존 이벤트를 삭제하지 않고 반대 방향 correction 이벤트를 추가한다.

#### DESK-INC-001 [P0] 사고 기록

- 사고 유형, 회차, 예약 선택, 시각, 메모, 사진을 입력한다.
- 오프라인에서는 초안만 저장하고 공식 제출은 온라인에서 한다.
- 안전 사고는 일반 메모보다 눈에 띄는 긴급 연락 절차를 먼저 보여준다.

#### DESK-INC-002 [P1] 운영자센터 연계

- 제출된 사고는 운영자센터 사건 큐에 생성된다.
- 운영자 답변이나 추가 자료 요청을 현장 데스크에서 확인한다.
- 현장 앱에서 고객 환불을 직접 실행하지 않는다.

### 7.7 설치·업데이트

#### DESK-PWA-001 [P0] 설치형 웹 앱

- manifest, 아이콘, standalone 표시, 안전한 캐시 정책을 제공한다.
- 앱 셸과 정적 자산만 cache-first로 두고 참석자 API 응답은 별도 암호화 저장소·수명 정책으로 관리한다.
- 인증 HTML이나 사용자 API 응답을 service worker 공용 캐시에 넣지 않는다.

#### DESK-PWA-002 [P0] 업데이트

- 새 service worker가 준비되면 진행 중 체크인과 미전송 큐가 없는 안전한 시점에 업데이트를 제안한다.
- 강제 새로고침으로 미전송 이벤트를 잃지 않는다.
- 필수 보안 업데이트는 만료 시각과 제한 기능을 명시한다.

### 7.8 오프라인 잔여 위험

#### DESK-OFF-001 [P0] 긴급 취소 인지 한계

- 마지막 동기화 직후 회차·예약이 긴급 취소되면 완전히 오프라인인 장치는 이를 알 수 없음을 운영 화면과 매뉴얼에 명시한다.
- 오프라인 체크인 결과는 서버 동기화 전까지 `잠정` 상태다.
- 안전 문제로 회차가 중지된 경우 파트너는 앱 알림만 믿지 않고 현장 전화 연락망을 함께 사용한다.
- 이 위험은 네트워크가 없는 한 기술적으로 제거할 수 없으며, 2시간 스냅샷 만료와 시작 전 갱신으로 노출 시간을 줄인다.

| `watchEffect` | 장치 진단·의존성 추적 실습 | 자동 의존 추적이 적절한 작은 영역에 제한 |
| lifecycle hooks | 카메라 시작·해제, listener 정리 | 장치 자원 수명 관리 |

| `<KeepAlive>` | 오늘·회차·스캔 탭 | 탭 전환 시 스캐너·스크롤 상태 보존과 해제 |

## 9. 로컬 저장 정책

| 데이터 | 저장소 | 수명 |
|---|---|---|
| 앱 셸·정적 자산 | service worker Cache Storage | 버전 교체 시 정리 |
| 사용자 세션 | 보안 쿠키, 메모리 요약 | 로그아웃·만료까지 |
| 당일 회차·최소 참석자 | IndexedDB | 운영 종료·권한 회수까지 |
| 미전송 체크인 이벤트 | IndexedDB | 서버 확인 또는 관리자 인계까지 |
| 카메라·UI 설정 | local storage | 사용자가 초기화할 때까지 |
| 사고 사진 초안 | IndexedDB 제한 영역 | 제출·취소 또는 24시간 |

브라우저 저장소의 암호화만으로 공유 장치 보안을 해결했다고 간주하지 않는다. 최소 수집, 짧은 수명, 장치 잠금, 세션 분리, 원격 해제를 함께 적용한다.

## 11. 인수 조건

### 11.1 핵심 E2E

1. 직원이 장치를 등록하고 사업장을 선택해 오늘 스냅샷을 동기화한다.
2. 4명 예약에서 2명 체크인 후 상태가 `PARTIAL`, 나머지 2명 후 `COMPLETE`가 된다.
3. 카메라 권한 거부 뒤 수동 확인 코드로 온라인 체크인을 완료한다.
4. 네트워크를 끊고 캐시된 QR을 체크인한 뒤 앱을 종료·재실행해도 큐가 남고 재연결 시 반영된다.
5. 응답이 유실된 체크인을 같은 clientEventId로 재전송해도 인원이 중복 증가하지 않는다.
6. 두 장치가 오프라인에서 같은 마지막 1명을 처리하면 서버는 하나만 반영하고 다른 장치를 공식 상태로 교정한다.
7. 캐시에 없는 QR은 오프라인에서 임의 승인되지 않는다.
8. 취소된 예약의 오프라인 이벤트가 늦게 도착하면 충돌 큐로 가고 참석으로 확정되지 않는다.
9. 역할 회수 뒤 온라인 연결 시 세션과 참석자 캐시가 제거된다.
10. 서버 체크인 정정은 슈퍼바이저 재인증과 사유가 있어야 하며 correction 이벤트로 남는다.

### 11.2 Vue·PWA 품질 기준

- 카메라 컴포넌트가 unmount/deactivate될 때 stream track과 listener를 정리한다.
- KeepAlive 복귀 때 이전 회차 카메라가 몰래 계속 실행되지 않는다.
- 큐 항목 key가 안정적이며 TransitionGroup 정렬에서 상태가 섞이지 않는다.
- 네트워크·권한·저장소 외부 상태 변경이 UI에 일관되게 반영된다.
- service worker 업데이트가 미전송 큐를 지우지 않는다.
- 스캐너와 결과 화면을 키보드·스크린리더 대체 흐름으로 사용할 수 있다.
- 앱 오류 뒤에도 동기화 큐 원본을 보존하고 재시도할 수 있다.

## 12. 단계별 출시

### 1단계 P0

로그인·장치, 오늘 회차, 참석자, QR·수동 체크인, 오프라인 큐, 재연결, 충돌, 정정, 사고 초안, PWA 업데이트.

### 2단계 P1

교대 체크리스트, 운영자센터 사고 답변, 현장 통계, 제한된 다중 사업장 빠른 전환.

### 3단계 P2 학습 확장

- Web Worker로 QR 해석 또는 대량 큐 변환을 옮기고 메인 스레드 반응을 비교한다.
- 격리된 `labs/`에서 render function, custom element, Options API 위젯을 구현한다.
- 다양한 브라우저의 background sync 지원 차이를 실험하고 지원되지 않을 때 수동 동기화를 유지한다.
