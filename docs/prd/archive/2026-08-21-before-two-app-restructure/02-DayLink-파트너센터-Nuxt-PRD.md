# PRD 02 — DayLink 파트너센터

- 제품명: DayLink Studio
- 기술: Nuxt + Vue + TypeScript
- 문서 버전: 1.0
- 우선순위 표기: P0 필수, P1 후속, P2 학습 확장
- 공통 정책: `00-DayLink-PRD-개요.md`를 따른다.

## 1. 제품 요약

체험을 제공하는 파트너가 입점하고, 상품을 심사 요청하고, 회차·정원·예약·정산·팀 권한을 관리하는 외부 업무 사이트다. 공개 안내 페이지, 서버 렌더링 온보딩, 상호작용이 많은 업무 화면을 한 Nuxt 앱 안에서 하이브리드 렌더링한다.

## 2. 목표와 제외 범위

### 2.1 목표

- 파트너가 도움 없이 입점과 첫 상품 심사 요청을 완료한다.
- 반복 일정과 예외 일정을 안전하게 만들고 기존 예약을 훼손하지 않는다.
- 심사 반려 사유와 수정 대상이 명확하게 연결된다.
- 예약 변경·회차 취소가 고객 알림·환불·정산으로 일관되게 이어진다.
- 파트너 조직 내 역할에 따라 메뉴와 데이터가 분리된다.
- Nuxt의 universal/CSR/prerender/hybrid, 파일 규칙, Nitro BFF, 데이터 패칭을 실제 화면에 적용한다.

### 2.2 제외 범위

- 파트너가 직접 임의 환불액을 송금하는 기능
- 실제 사업자·계좌 검증과 실제 정산 지급
- 여러 사업자 법인을 하나의 계약으로 묶는 기능
- 외부 캘린더 양방향 동기화
- 고급 회계·세금계산서 발행

## 3. 사용자와 역할

| 역할 | 할 수 있는 일 | 제한 |
|---|---|---|
| 소유자 | 입점, 상품·회차·예약, 팀, 정산, 계정 폐쇄 요청 | 심사 승인, 원장 직접 수정 불가 |
| 매니저 | 상품·회차·예약 운영, 현장 직원 초대 | 정산계좌, 소유권 변경 불가 |
| 콘텐츠 편집자 | 상품 초안·미디어·미리보기 | 심사 요청·게시·예약 조회 불가 |
| 회계 담당 | 정산서·조정 내역 조회와 내보내기 | 고객 상세·상품 변경 불가 |

사용자는 여러 파트너에 초대될 수 있다. 현재 선택한 파트너가 모든 요청에 명시되며, 서버는 소속과 역할을 다시 검사한다.

## 4. 성공 지표

| 지표 | 정의 |
|---|---|
| 입점 완료율 | 입점 시작 파트너 중 `ACTIVE` 도달 비율 |
| 첫 상품 제출 소요 | 입점 활성화부터 첫 `SUBMITTED`까지 걸린 시간 |
| 1차 심사 통과율 | 수정 요청 없이 승인된 상품 비율 |
| 자동 저장 복구율 | 오류·이탈 후 최신 초안을 복구한 비율 |
| 회차 충돌 차단률 | 기존 예약을 침해할 변경을 제출 전에 탐지한 비율 |
| 파트너 셀프 처리율 | 운영자 개입 없이 해결한 예약 조회·내보내기 비율 |
| 정산 대사 문의율 | 정산 항목 설명을 찾지 못해 문의로 이어진 비율 |

## 5. 정보 구조와 렌더링 전략

| 경로 | 화면 | 접근 | 렌더링 전략 |
|---|---|---|---|
| `/` | 파트너 소개 | 공개 | prerender + 장기 캐시 |
| `/guide/[...slug]` | 운영 가이드 | 공개 | Nuxt Content 기반 prerender |
| `/login` | 로그인 | 공개 | universal, 캐시 금지 |
| `/invite/[token]` | 팀 초대 수락 | 서명 토큰 | universal, 캐시 금지 |
| `/onboarding/**` | 입점 단계 | 로그인 | universal SSR |
| `/app` | 대시보드 | 파트너 구성원 | universal, 사용자별 캐시 금지 |
| `/app/experiences` | 상품 목록 | 권한별 | universal + client navigation |
| `/app/experiences/new` | 상품 작성 | 편집 권한 | universal shell + client form |
| `/app/experiences/[id]/edit` | 상품 수정 | 편집 권한 | universal shell + client form |
| `/app/schedules` | 회차 달력 | 운영 권한 | CSR, 브라우저 중심 달력 |
| `/app/bookings` | 예약 목록 | 운영 권한 | universal + 서버 필터 |
| `/app/bookings/[id]` | 예약 상세 | 운영 권한 | universal |
| `/app/settlements` | 정산 목록 | 소유자·회계 | universal |
| `/app/team` | 팀·권한 | 소유자·매니저 일부 | universal |
| `/app/settings` | 사업장·알림 설정 | 권한별 | universal |

`routeRules`로 공개 가이드는 사전 생성하고, 온보딩과 일반 업무 페이지는 universal, 무거운 달력은 CSR로 분리한다. 인증 화면을 CDN 공용 캐시에 올리지 않는다.

## 6. 기능 요구사항

### 6.1 공개 소개·가이드

#### PTN-PUB-001 [P0] 파트너 소개

- 서비스 운영 방식, 심사 절차, 수수료 예시, 정산 주기, 자주 묻는 질문을 제공한다.
- 실제 수익을 보장하는 표현을 사용하지 않는다.
- 가입 전에 필요한 정보와 문서를 체크리스트로 보여준다.

#### PTN-PUB-002 [P0] 운영 가이드

- 상품 작성, 일정, 취소, 현장 운영, 정산 카테고리의 문서를 제공한다.
- 문서는 버전과 최종 수정일을 표시한다.
- 업무 화면의 도움말 링크는 관련 문서의 정확한 절로 이동한다.

### 6.2 로그인·조직 선택

#### PTN-AUTH-001 [P0] 로그인

- 이메일 magic link 또는 모의 소셜 로그인을 제공한다.
- 고객 웹 세션과 파트너 세션을 분리한다.
- 초대 링크에서 로그인한 뒤 원래 초대로 돌아온다.

#### PTN-AUTH-002 [P0] 파트너 전환

- 여러 파트너 소속 사용자는 헤더에서 현재 파트너를 바꿀 수 있다.
- 전환 시 이전 파트너의 query cache, draft, 선택 상태를 제거한다.
- URL의 partnerId만 바꿔 다른 조직 데이터에 접근할 수 없어야 한다.

### 6.3 입점

#### PTN-ONB-001 [P0] 단계형 입점

- 단계: 기본 정보 → 사업장 → 담당자 → 정산 정보 → 약관 → 검토.
- 각 단계는 독립 저장되며 완료·오류 상태가 보인다.
- 뒤로 가도 이미 저장한 값이 유지된다.

#### PTN-ONB-002 [P0] 문서 업로드

- 테스트 사업자 문서와 계좌 확인 파일을 업로드한다.
- 허용 형식, 크기, 진행률, 실패 원인, 재시도를 제공한다.
- 업로드 완료 전 다음 단계로 갈 수 없고 삭제된 파일 키를 제출할 수 없다.

#### PTN-ONB-003 [P0] 검토 요청·수정

- 누락·형식 오류를 단계별로 요약한다.
- 제출 후 검토 중에는 심사 대상 필드를 잠그되 연락처 같은 비핵심 정보는 변경할 수 있다.
- 반려 시 사유가 해당 필드와 연결되고 수정 뒤 재제출할 수 있다.

### 6.4 대시보드

#### PTN-DASH-001 [P0] 오늘의 운영

- 오늘 회차, 예약 인원, 남은 좌석, 변경 요청, 미확인 공지를 표시한다.
- 역할상 볼 수 없는 금액이나 고객 정보는 위젯 자체를 숨긴다.
- 위젯별 오류가 전체 대시보드를 막지 않는다.

#### PTN-DASH-002 [P1] 추세

- 기간별 예약, 취소, 참석률, 예상 정산액을 시각화한다.
- 표 대체 텍스트와 원자료 다운로드를 제공한다.
- 시각화 값은 운영 원장과 같은 집계 기준을 사용한다.

### 6.5 상품 작성·심사

#### PTN-EXP-001 [P0] 상품 편집기

- 단계: 기본 정보 → 설명·미디어 → 장소·접근성 → 가격 → 운영·취소 정책 → 검토.
- 필수 필드와 글자 수, 이미지 수, 접근성 정보를 단계마다 검증한다.
- 초안은 3초 debounce 또는 단계 이동 때 자동 저장한다.
- 서버 version 충돌 시 덮어쓰지 말고 내 변경과 서버 변경을 비교한다.

#### PTN-EXP-002 [P0] 미디어 관리

- 이미지 최대 20장, 대표 이미지 1장, 드래그 정렬, 대체 텍스트를 지원한다.
- 업로드 중 이탈 경고와 실패 항목 개별 재시도를 제공한다.
- 삭제는 상품 저장과 별개로 고아 파일 정리 정책을 갖는다.

#### PTN-EXP-003 [P0] 가격·정책

- 정상가, 인원별 가격 조건, 판매 마감 시간, 취소 정책 템플릿을 선택한다.
- 음수·역전 구간·겹치는 유효 기간을 차단한다.
- 자유 입력 정책이 아니라 운영자가 승인한 정책 버전을 참조한다.

#### PTN-EXP-004 [P0] 미리보기

- 저장된 최신 초안을 고객 웹 모양으로 확인한다.
- 짧은 만료의 서명된 미리보기 링크를 발급한다.
- 링크를 가진 사람도 예약·검색 노출은 할 수 없다.

#### PTN-EXP-005 [P0] 심사 요청

- 제출 전 누락, 금칙 표현, 이미지 대체 텍스트, 일정 부재를 검사한다.
- 요청 후 심사 스냅샷을 만들며 이후 초안 수정은 다음 버전에 쌓인다.
- 반려 사유는 필드, 심사 의견, 참고 가이드와 함께 표시한다.

#### PTN-EXP-006 [P0] 게시·중지

- 승인된 버전만 게시할 수 있다.
- 게시 중지는 신규 검색·hold를 막지만 기존 예약과 현장 목록은 보존한다.
- 예약이 남은 상품은 보관 처리 전에 영향을 보여준다.

### 6.6 일정·재고

#### PTN-SCH-001 [P0] 반복 회차 생성

- 기간, 요일, 시작 시각, 소요 시간, 정원, 판매 마감 시각으로 회차를 일괄 생성한다.
- 생성 전 예상 회차 수와 휴무·중복 충돌을 미리 보여준다.
- 한 번에 생성 가능한 기간과 회차 수를 제한한다.

#### PTN-SCH-002 [P0] 예외 일정

- 특정 날짜 휴무, 시간·정원 변경, 추가 회차를 지원한다.
- 반복 규칙을 바꿀 때 기존 예외의 유지·삭제 영향을 미리 계산한다.
- 과거 회차는 운영 기록으로만 조회하고 일반 수정할 수 없다.

#### PTN-SCH-003 [P0] 정원 변경

- 정원을 늘릴 수 있다.
- 확정 예약 인원과 활성 hold 합계보다 낮게 줄일 수 없다.
- 활성 hold 때문에 줄일 수 없다면 가장 늦은 만료 시각을 알려준다.

#### PTN-SCH-004 [P0] 예약 보유 회차 변경

- 날짜·시각·장소 변경은 일반 편집으로 처리하지 않는다.
- 변경 전후, 영향 고객 수, 환불 비용을 보여주고 `일정 변경 제안`을 생성한다.
- 제안 생성 시 영향 예약 인원만큼 대체 회차 정원을 우선 확보하며, 확보할 수 없으면 제안을 만들지 않는다.
- 대체 회차는 고객 응답이 끝날 때까지 일반 판매 정원과 분리한다.
- 고객 수락 전까지 기존 예약 조건이 유효하고, 수락한 고객만 응답 기한에 대체 회차로 원자적으로 이동한다.
- 거절·미응답 예약은 응답 기한에 전액 취소한다.

#### PTN-SCH-005 [P0] 회차 취소

- 사유와 영향 예약 수를 확인하고 재인증 뒤 취소한다.
- 시작 후에는 일반 취소할 수 없고 운영 사고로 넘긴다.
- Core API가 예약 취소, 전액 환불, 정산 조정, 알림 이벤트를 한 업무 흐름으로 처리한다.

### 6.7 예약 관리

#### PTN-BKG-001 [P0] 예약 목록

- 날짜, 회차, 상태, 이름 일부, 예약번호로 검색한다.
- 서버 정렬·필터·cursor pagination을 사용한다.
- 고객 연락처는 기본 마스킹하고 업무상 필요한 기간에만 권한자가 확인한다.

#### PTN-BKG-002 [P0] 예약 상세

- 예약·결제 요약, 참석 인원, 체크인 상태, 취소 이력을 보여준다.
- 결제 전체 거래키와 민감정보는 노출하지 않는다.
- 파트너는 예약 상태를 임의로 확정·환불 처리할 수 없다.

#### PTN-BKG-003 [P0] 참석자 내보내기

- 지정 회차의 최소 정보만 CSV로 내보낸다.
- 대량 파일은 비동기 작업으로 만들고 만료되는 다운로드 링크를 제공한다.
- 요청자, 조건, 다운로드 시각을 감사 기록에 남긴다.

#### PTN-BKG-004 [P1] 고객 안내

- 확정 예약자에게 준비물·도착 안내를 템플릿으로 발송한다.
- 광고성 메시지와 운영 안내를 구분한다.
- 발송 실패가 예약 상태를 바꾸지 않으며 재시도 상태를 보여준다.

### 6.8 정산

#### PTN-SET-001 [P0] 정산 목록

- 정산 기간, 상태, 예약 매출, 수수료, 환불·조정, 예상 지급액을 표시한다.
- 집계 금액을 클릭하면 구성 원장 항목으로 드릴다운한다.
- 원장 항목을 삭제하거나 직접 수정할 수 없다.

#### PTN-SET-002 [P0] 정산서 내보내기

- 조회 당시 필터와 데이터 기준 시각을 포함한 CSV를 생성한다.
- 파일 생성 중, 완료, 실패, 만료 상태를 제공한다.
- 회계 담당은 정산 파일만 받고 고객 연락처는 받을 수 없다.

#### PTN-SET-003 [P1] 이의 제기

- 파트너는 특정 원장 항목을 선택해 사유와 증빙을 제출한다.
- 운영자 답변과 조정 항목을 동일 사건 타임라인에서 확인한다.

### 6.9 팀·설정

#### PTN-TEAM-001 [P0] 팀 초대

- 이메일, 역할, 사업장 범위를 지정해 만료 초대를 보낸다.
- 이미 가입된 사용자는 승인 후 소속이 추가되고, 미가입자는 가입 뒤 수락한다.
- 마지막 소유자는 제거·강등할 수 없다.

#### PTN-TEAM-002 [P0] 역할 변경·회수

- 권한 변경은 즉시 새 요청부터 적용한다.
- 이미 열린 화면의 다음 API 요청도 거부되어야 한다.
- 변경자·대상·이전·이후 역할을 감사 기록에 남긴다.

#### PTN-CFG-001 [P0] 알림 설정

- 예약 확정, 취소, 심사 결과, 정산 완료를 채널별로 설정한다.
- 법적·보안상 필수 알림은 끌 수 없고 이유를 표시한다.

## 7. Nuxt 학습 요구사항 연결

| Nuxt/Vue 기능 | 적용 요구사항 | 구현 의도 |
|---|---|---|
| `app/pages` 파일 라우팅 | 전체 화면 | 동적·중첩 라우트와 page meta 학습 |
| layouts | 공개, 온보딩, 업무 셸 | 역할별 공통 UI와 전환 분리 |
| route middleware | 로그인, 입점 상태, 역할 | 이동 전 UX 제어. 최종 권한은 Core API |
| universal rendering | 온보딩, 업무 읽기 | SSR·hydration과 인증 데이터 처리 |
| `routeRules` hybrid rendering | 공개 가이드, 달력, 앱 | prerender·SSR·CSR을 페이지 성격에 맞게 비교 |
| `useFetch` | Nuxt server API 호출 | SSR payload 재사용과 요청 상태 처리 |
| `useAsyncData` | 여러 Core API 집계 대시보드 | 명시적 key, refresh, dedupe, 오류 처리 |
| `useState` | SSR 안전 파트너 선택·단계 상태 | 요청 간 상태 누수 방지 |
| Pinia | 복잡한 상품 초안·달력 편집 | 장기 편집 세션과 devtools 추적 |
| composables | 업로드, 권한, 자동저장, pagination | Vue 반응 로직 재사용 |
| plugins | API client, telemetry, validation locale | 앱 생성 시 주입과 client/server 구분 |
| runtime config | Core API URL·서버 비밀 | 서버 전용 비밀과 공개 설정 분리 |
| app config | 테마·표시 설정 | 클라이언트 노출 가능한 반응형 설정 |
| `server/api`·`server/routes` | 세션 BFF, 서명 업로드, export status | 브라우저 맞춤 API와 파일 응답 |
| server middleware/plugin | traceId, 세션 문맥, 로깅 | Nitro 요청 수명주기 학습 |
| Nuxt Content | 운영 가이드 | 파일 콘텐츠, 정적 생성, 검색 인덱스 |
| modules | Content·Image·필수 통합 | Nuxt 생태계 모듈과 설정 학습 |
| layers | 업무 셸·토큰·테이블 기반 | 제품 내부 재사용 계층. 별도 앱과 UI 공유는 금지 |
| head/SEO | 소개·가이드·미리보기 | 메타데이터, noindex, canonical |
| error page·`createError` | 권한, 미존재, 장애 | HTTP 의미와 사용자 복구 동작 분리 |
| `<ClientOnly>` | 브라우저 의존 달력·편집기 | SSR 불가능 컴포넌트 경계 |
| lazy component | 차트, 미디어 편집기 | 초기 번들 분리 |

Nuxt server는 Core API를 대체하지 않는다. 세션, 입력 정규화, 응답 조합, 업로드 서명, export 상태 전달만 담당한다. 재고·가격·환불·정산 규칙은 Core API에 둔다.

## 8. 자동 저장·동시 편집 정책

- 편집 화면 진입 시 `draftVersion`을 받는다.
- 자동 저장은 변경된 필드만 보내고 마지막 성공 시각을 표시한다.
- 요청 도중 추가 변경이 생기면 완료 후 최신 변경을 다시 저장한다.
- 409 충돌 시 자동 덮어쓰지 않는다.
- 서버 버전과 내 변경을 필드 단위로 비교해 `서버 값 유지`, `내 값 적용`을 선택한다.
- 심사 제출은 제출 시점 스냅샷을 만들며 이후 자동 저장 초안과 분리한다.

## 10. 인수 조건

### 10.1 핵심 E2E

1. 신규 파트너가 입점 정보를 저장·이탈·복귀한 뒤 검토 요청을 완료한다.
2. 콘텐츠 편집자가 상품을 작성하고 소유자가 심사 요청하며 운영자 승인 후 게시한다.
3. 파트너 미리보기는 최신 저장 초안을 보이지만 예약과 검색 색인은 허용하지 않는다.
4. 두 탭에서 같은 초안을 수정하면 version 충돌을 감지하고 비교 화면을 제공한다.
5. 반복 회차 생성 전 중복과 생성 건수를 보여주고 제한 초과를 차단한다.
6. 확정 8명과 활성 hold 2명이 있는 회차 정원을 9명으로 줄이지 못한다.
7. 예약이 있는 회차의 날짜 변경은 일반 저장이 아니라 고객 동의 흐름으로만 진행한다.
8. 회차 취소 한 번으로 예약 취소·환불·정산 조정·알림 이벤트가 연결되고 중복 실행되지 않는다.
9. 회계 담당은 정산 CSV를 받을 수 있지만 고객 연락처 export에는 접근할 수 없다.
10. 파트너를 전환한 직후 이전 조직의 캐시 데이터가 잠깐도 보이지 않는다.

### 10.2 Nuxt 품질 기준

- prerender, universal, CSR 경로가 빌드 결과와 네트워크 기록으로 구분된다.
- SSR에서 가져온 데이터가 hydration 때 이유 없이 중복 호출되지 않는다.
- server-only 비밀이 client bundle과 payload에 포함되지 않는다.
- route middleware를 우회한 직접 API 요청도 Core API에서 거부된다.
- 달력 SDK나 편집기 로딩 실패가 상품 목록 같은 다른 업무를 막지 않는다.

## 11. 단계별 출시

### 1단계 P0

소개·가이드, 로그인, 입점, 상품 작성·심사·게시, 회차·정원, 예약 목록·내보내기, 정산 조회, 팀 권한.

### 2단계 P1

추세 차트, 고객 안내, 정산 이의 제기, 일정 변경 동의 현황, 세분화된 사업장 권한.

### 3단계 P2 학습 확장

- 업무 셸을 Nuxt layer로 분리하고 두 번째 가상 브랜드 설정을 얹어 확장성을 검증한다.
- 공개 가이드 일부를 요청 시 SSR과 prerender로 각각 측정해 결과를 ADR로 남긴다.
- 격리된 `labs/`에 server-only page, custom module, Vue Options API로 작성한 레거시 위젯을 둔다.
