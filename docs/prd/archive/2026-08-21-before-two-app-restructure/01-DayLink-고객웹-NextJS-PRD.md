# PRD 01 — DayLink 고객 웹

- 제품명: DayLink
- 기술: Next.js App Router + React + TypeScript
- 문서 버전: 1.0
- 우선순위 표기: P0 필수, P1 후속, P2 학습 확장
- 공통 정책: `00-DayLink-PRD-개요.md`를 따른다.

## 1. 제품 요약

고객이 지역 클래스·체험을 검색하고 회차별 남은 좌석과 최종 가격을 확인해 테스트 결제까지 완료하는 모바일 우선 B2C 웹이다. 공개 콘텐츠의 검색 노출과 초기 표시 성능, 로그인 이후의 안전한 거래 흐름을 한 제품에서 다룬다.

## 2. 목표와 제외 범위

### 2.1 목표

- 비회원도 검색 결과와 상품 상세를 빠르게 확인한다.
- 로그인 고객은 좌석 선점부터 결제·예약 확인까지 중단 없이 완료한다.
- 가격, 재고, 취소 규정을 결제 직전에 다시 확정한다.
- 결제 응답 유실·중복 호출에도 예약 상태가 일관된다.
- 공개 페이지에는 적절한 SEO, 구조화 데이터, 공유 미리보기를 제공한다.
- Next.js의 서버·클라이언트 경계, 렌더링 전략, 캐시 무효화를 실제 요구사항에 연결한다.

### 2.2 제외 범위

- 여러 파트너·회차를 한 주문에 담는 장바구니
- 실제 카드 결제와 실제 현금 환불
- 해외 통화·해외 시간대·배송 상품
- 고객 간 커뮤니티, 실시간 채팅
- 네이티브 앱 전용 기능

## 3. 사용자

### 3.1 비회원 탐색자

- 지역과 날짜를 기준으로 체험을 비교한다.
- 가격과 후기, 남은 좌석을 확인한 뒤 예약 의사를 결정한다.

### 3.2 로그인 고객

- 본인과 동행 인원의 예약을 결제한다.
- 예약 QR, 장소, 준비물을 확인한다.
- 규정에 따라 취소하고 참석 후 후기를 작성한다.

### 3.3 고객지원 유입 고객

- 결제가 끝났는데 화면이 멈춘 상황에서 예약 상태를 다시 확인한다.
- 취소·환불 진행 상태와 문의 식별번호를 확인한다.

## 4. 성공 지표

학습용 서비스이므로 숫자 자체보다 이벤트가 정확히 수집되고 병목을 설명할 수 있는지가 중요하다.

| 지표 | 정의 |
|---|---|
| 검색→상세 진입률 | 검색 결과 노출 세션 중 상세 진입 비율 |
| 상세→회차 선택률 | 상세 방문 중 예약 가능한 회차 선택 비율 |
| hold→예약 확정률 | 좌석 선점 건 중 확정 예약 비율 |
| 결제 불확실 상태 회복률 | 결제 반환 페이지가 웹훅 결과를 재조회해 최종 상태를 표시한 비율 |
| 검색 결과 0건 비율 | 필터 조합별 0건 비율 |
| 취소 셀프 처리율 | CS 개입 없이 완료된 취소 비율 |
| Core Web Vitals 통과율 | 실제 측정 대상 URL의 good 기준 통과 비율 |

## 5. 정보 구조와 경로

| 경로 | 화면 | 접근 | 기본 렌더링·캐시 |
|---|---|---|---|
| `/` | 홈 | 공개 | 정적 생성 + 주기 재검증 |
| `/regions/[region]` | 지역 랜딩 | 공개 | 정적 생성 + 태그 재검증 |
| `/categories/[category]` | 카테고리 랜딩 | 공개 | 정적 생성 + 태그 재검증 |
| `/search` | 검색 결과 | 공개 | 동적 SSR, 검색조건은 URL |
| `/experiences/[slug]` | 상품 상세 | 공개 | ISR, 회차·좌석만 동적 조회 |
| `/experiences/[slug]/reviews` | 후기 전체 | 공개 | SSR + cursor pagination |
| `/preview/[token]` | 미게시 상품 미리보기 | 서명 토큰 | 동적, 캐시 금지 |
| `/login` | 로그인 | 공개 | 동적 |
| `/checkout/[holdId]` | 결제 | 고객 | 동적, 캐시 금지 |
| `/payment/return` | 결제 복귀 | 고객 | 동적, 상태 재조회 |
| `/account` | 내 계정 요약 | 고객 | 동적, 병렬 영역 |
| `/account/bookings` | 예약 목록 | 고객 | 동적 |
| `/account/bookings/[bookingId]` | 예약 상세·QR | 소유 고객 | 동적 |
| `/account/favorites` | 찜 | 고객 | 동적 |
| `/account/reviews/new` | 후기 작성 | 작성 자격 고객 | 동적 |
| `/help/[...slug]` | 도움말 | 공개 | 정적 생성 |

검색 결과에서 상품을 누르면 가로채기 라우트로 빠른 상세 모달을 띄운다. URL을 직접 열거나 새로고침하면 전체 상세 페이지를 보여야 한다.

`/account`에서는 `예정 예약`과 `처리 중 알림`을 병렬 라우트로 독립 로딩한다. 한 영역 실패가 전체 계정 화면을 막지 않아야 한다.

## 6. 기능 요구사항

### 6.1 홈·탐색

#### B2C-HOME-001 [P0] 홈 구성

- 현재 판매 중인 지역, 카테고리, 추천 체험을 노출한다.
- 서버에서 기본 콘텐츠를 렌더링하고 개인화가 필요한 최근 본 상품만 클라이언트에서 추가한다.
- 추천 영역이 실패해도 지역·카테고리 탐색은 유지한다.

#### B2C-HOME-002 [P0] 검색 진입

- 지역, 날짜, 인원을 입력할 수 있다.
- 날짜가 과거이거나 인원이 1~6 범위를 벗어나면 이동 전에 오류를 알린다.
- 검색 조건은 공유·뒤로가기 가능한 URL query로 직렬화한다.

#### B2C-HOME-003 [P1] 최근 본 상품

- 비회원은 브라우저에 최대 20개, 회원은 서버에 최대 50개를 보관한다.
- 로그인 직후 비회원 기록을 회원 기록과 중복 제거해 합친다.

### 6.2 검색 결과

#### B2C-SRCH-001 [P0] 필터와 정렬

- 필터: 지역, 날짜 범위, 카테고리, 가격 범위, 최소 평점, 예약 가능 여부, 소요 시간.
- 정렬: 추천, 가격 낮은 순, 평점 순, 가까운 날짜 순.
- 필터 변경은 URL에 반영하며, 입력 중인 가격 슬라이더는 확정 시에만 서버 요청을 보낸다.

#### B2C-SRCH-002 [P0] 결과 카드

- 대표 이미지, 제목, 지역, 시작 가격, 평점·후기 수, 가장 가까운 가능 일자를 표시한다.
- `시작 가격`과 특정 회차의 최종 가격을 혼동하지 않게 문구를 구분한다.
- 품절 상품은 예약 가능 필터가 꺼진 경우에만 품절 표시로 노출할 수 있다.

#### B2C-SRCH-003 [P0] 빈 결과·오류

- 0건이면 사용자가 적용한 조건과 제거 제안을 보여준다.
- API 오류를 0건으로 위장하지 않고 오류와 재시도 버튼을 보여준다.
- 이전 성공 결과가 있다면 흐리게 유지하되 최신 정보가 아님을 표시한다.

#### B2C-SRCH-004 [P1] 지도 연계

- 지도 이동 후 `이 지역에서 다시 검색`을 눌렀을 때만 요청한다.
- 지도 SDK는 사용자 상호작용 또는 지도 영역 진입 후 지연 로딩한다.
- 지도 없이도 동일한 결과와 기능을 목록에서 사용할 수 있다.

### 6.3 상품 상세

#### B2C-EXP-001 [P0] 기본 정보

- 이미지, 제목, 호스트, 장소 범위, 설명, 소요 시간, 포함·불포함 항목, 준비물, 연령·접근성 제한, 취소 규정을 표시한다.
- HTML 입력은 허용 목록 기반으로 정제된 결과만 렌더링한다.
- 승인된 게시 버전을 표시하며 파트너의 미심사 초안은 노출하지 않는다.

#### B2C-EXP-002 [P0] 회차·인원 선택

- 월 단위 가능 날짜와 선택 날짜의 회차를 표시한다.
- 회차를 선택할 때 최신 잔여 좌석과 예상 금액을 조회한다.
- 예상 금액은 결제 확정 금액이 아님을 명시한다.
- 마감·품절·시작 임박 규칙으로 선택 불가 사유를 보여준다.

#### B2C-EXP-003 [P0] 후기 요약

- 평균 평점, 분포, 최신 공개 후기 일부를 보여준다.
- 후기 로딩 실패가 상품·예약 영역을 막지 않는다.
- 신고·비공개 후기는 평균 계산과 목록에서 제외한다.

#### B2C-EXP-004 [P0] 미리보기

- 파트너센터가 발급한 1회성 또는 짧은 만료 토큰으로 미게시 버전을 확인한다.
- 검색엔진 색인과 공유 미리보기를 차단한다.
- 미리보기에서는 예약 버튼을 비활성화한다.

#### B2C-EXP-005 [P1] 빠른 상세 모달

- 검색 맥락에서 열면 URL이 바뀌는 모달로 표시한다.
- 닫으면 검색 스크롤과 필터가 복원된다.
- 직접 접근 시 전체 상세로 동작한다.

### 6.4 인증

#### B2C-AUTH-001 [P0] 로그인

- 이메일 magic link 또는 모의 소셜 로그인을 제공한다.
- 예약 버튼을 누른 비회원은 로그인 후 선택한 상품·회차·인원 화면으로 돌아온다.
- 좌석 hold는 로그인이 끝난 뒤 생성한다.

#### B2C-AUTH-002 [P0] 세션

- 세션은 HttpOnly 쿠키로 관리한다.
- 인증 만료 시 읽기 화면은 유지하고, 변경 요청 시 재로그인 후 한 번만 재개한다.
- 결제 제출 자체는 자동 재전송하지 않는다.

### 6.5 좌석 선점·결제

#### B2C-CHK-001 [P0] 최종 견적과 hold

- 고객이 회차·인원을 확정하면 Core API에 최종 견적과 좌석 선점을 한 요청으로 요구한다.
- 응답에는 정상가, 할인, 최종액, 정책 버전, 만료 시각을 포함한다.
- hold는 10분 후 만료되며 서버 시간을 기준으로 카운트다운한다.
- 재고 부족, 가격 변경, 판매 중단 시 바뀐 내용을 구체적으로 보여주고 고객 확인을 다시 받는다.

#### B2C-CHK-002 [P0] 쿠폰

- 사용 가능한 쿠폰만 표시하고 직접 코드 입력도 허용한다.
- 쿠폰 혜택 한도가 있으면 hold와 함께 임시 점유하고 만료 시 해제한다.
- 쿠폰 적용 후 가격이 바뀌면 새 견적 스냅샷을 사용한다.

#### B2C-CHK-003 [P0] 결제 동의·제출

- 예약자 연락처, 최종 금액, 일정, 장소, 취소 규정, 개인정보 제공 동의를 한 화면에서 최종 확인한다.
- 결제 버튼은 한 번 누른 뒤 진행 상태가 명확해야 하며 중복 클릭을 막는다.
- 요청에는 멱등 키를 사용한다.
- 클라이언트 성공 응답만으로 예약을 확정 표시하지 않는다.

#### B2C-CHK-004 [P0] 결제 복귀와 불확실 상태

- 결제사 복귀 시 Core API의 예약 상태를 조회한다.
- 아직 웹훅이 처리되지 않았으면 `확인 중`을 표시하고 제한 횟수로 재조회한다.
- 재조회가 끝나도 불확실하면 예약 내역 링크와 문의용 traceId를 제공한다.
- 늦게 성공한 웹훅은 새 예약을 만들지 않고 기존 예약을 확정한다.

#### B2C-CHK-005 [P0] 실패·만료

- 결제 거절 시 hold가 남아 있는 동안 다른 테스트 수단으로 재시도할 수 있다.
- hold 만료 후에는 이전 결제를 재사용하지 않고 새 가격·좌석을 확인한다.
- 결제 승인 후 예약 확정에 실패한 비정상 상태는 자동 보상 또는 운영자 큐로 보낸다.

### 6.6 예약 관리

#### B2C-BKG-001 [P0] 예약 목록·상세

- 예정, 지난 예약, 취소·환불 처리 중으로 나눠 표시한다.
- 예약 상세에 상태, 인원, 결제 내역, 장소, 준비물, 호스트 연락 정책, QR을 표시한다.
- QR에는 개인정보나 순차 예약번호를 직접 넣지 않고 불투명한 참석 토큰만 넣는다.

#### B2C-BKG-002 [P0] 취소 예상액

- 취소 버튼을 누르면 서버가 현재 시각과 예약 정책 스냅샷으로 환불 예상액을 계산한다.
- 확정 전 환불액, 수수료, 처리 예상 상태를 표시한다.
- 이미 체크인했거나 취소 가능 시각을 지났다면 정확한 차단 사유를 표시한다.

#### B2C-BKG-003 [P0] 취소 실행

- 고객 확인 뒤 멱등 키와 함께 취소 명령을 보낸다.
- 처리 중 화면을 이탈해도 예약 상세에서 진행 상태를 이어 볼 수 있다.
- 중복 요청은 같은 취소 결과를 반환한다.

#### B2C-BKG-004 [P1] 일정 변경 제안 응답

- 파트너가 날짜·장소 변경을 제안한 경우 기존 내용과 변경 내용을 비교한다.
- 고객은 새 조건 수락 또는 전액 취소 중 하나를 선택한다.
- 응답 기한까지 미응답이면 전액 취소하는 정책을 사용한다.

### 6.7 찜·후기

#### B2C-FAV-001 [P0] 찜

- 로그인 고객은 목록·상세에서 즉시 찜 상태를 바꿀 수 있다.
- 화면은 낙관적으로 반영하되 서버 실패 시 원복하고 이유를 알린다.
- 동일 요청의 빠른 반복으로 최종 상태가 뒤집히지 않게 순서를 관리한다.

#### B2C-REV-001 [P0] 후기 자격

- `COMPLETED`이고 실제 체크인된 예약당 하나의 후기만 작성할 수 있다.
- 전액 환불, 취소, 미참석 예약은 작성할 수 없다.
- 별점 1~5, 본문, 선택 이미지 최대 5장을 받는다.

#### B2C-REV-002 [P0] 후기 작성·수정

- 제출 전 임시 이미지 업로드 실패를 복구할 수 있다.
- 제출 직후 화면에 낙관적으로 반영하되 심사 상태를 표시한다.
- 작성 후 7일 이내 수정 가능, 삭제는 소프트 삭제로 처리한다.

### 6.8 도움말·오류

#### B2C-SUP-001 [P0] 도움말

- 예약, 결제, 취소, 현장 이용 카테고리로 정적 도움말을 제공한다.
- 예약 관련 문의를 시작할 때 로그인 고객의 예약번호를 선택할 수 있다.

#### B2C-ERR-001 [P0] 경계별 오류 처리

- 전역, 검색 결과, 상품 상세 후기, 결제, 계정 병렬 영역에 서로 다른 오류 경계를 둔다.
- 404, 권한 없음, 삭제됨, 일시 장애를 같은 화면으로 뭉개지 않는다.
- 모든 오류 화면은 가능한 재시도와 안전한 다음 행동을 제공한다.

## 7. Next.js 학습 요구사항 연결

| Next.js/React 기능 | 적용 요구사항 | 구현 의도 |
|---|---|---|
| Server Components | 홈, 지역, 상세, 계정 읽기 | 데이터 접근과 비밀값을 서버에 두고 클라이언트 JS 축소 |
| Client Components | 필터, 달력, 카운트다운, 결제 UI | 이벤트·브라우저 API가 필요한 경계만 클라이언트화 |
| 중첩 layout·route group | 공개, 인증, 계정, 결제 영역 | 서로 다른 셸과 권한을 URL 왜곡 없이 분리 |
| dynamic/catch-all route | 상품·지역·도움말 | 파일 기반 라우팅과 매개변수 검증 |
| parallel route | 계정 요약 | 독립 로딩·오류 처리 |
| intercepting route | 검색의 빠른 상세 | URL 보존 모달과 직접 접근 전체 페이지 비교 |
| `loading`, `error`, `not-found` | 모든 주요 세그먼트 | 대기·실패·부재 상태를 구조적으로 분리 |
| Suspense·streaming | 상세 후기, 계정 병렬 영역 | 중요한 콘텐츠 먼저 표시 |
| 정적 생성·ISR·태그 재검증 | 홈, 지역, 상품 게시 버전 | 공개 콘텐츠 캐시와 승인·게시 이벤트 무효화 |
| 동적 SSR·`no-store` | 검색, 결제, 계정 | 사용자·재고 데이터를 공용 캐시에 섞지 않음 |
| Server Actions | 찜, 후기, 고객 취소 의도 제출 | 인증된 폼 mutation과 pending/error 상태 학습 |
| Route Handlers | 인증 callback, 업로드 서명, 클라이언트용 BFF | 브라우저 전용 입출력과 세션 경계 처리 |
| `cookies`, `headers`, redirect | 인증·원래 경로 복귀 | 요청 문맥과 안전한 이동 처리 |
| Draft Mode | 미게시 상품 미리보기 | 캐시된 공개본과 초안 분리 |
| Metadata·sitemap·robots | 공개 랜딩·상품 | 검색·공유 메타데이터와 색인 제어 |
| Image·Font·Script 최적화 | 카드, 상세, 지도·결제 SDK | 자산 최적화와 외부 스크립트 지연 |
| Proxy/Middleware | 로그인 전 경로 기록, 보안 헤더 | 빠른 1차 분기. 최종 권한 검사는 Core API |
| instrumentation | trace, 성능, 서버 오류 | 요청 단위 관측성 |
| `useOptimistic` | 찜·후기 | 낙관적 UI와 실패 원복 |
| `useTransition` | URL 필터 전환 | 입력 반응을 막지 않는 비긴급 갱신 |

Server Component가 같은 앱의 Route Handler를 다시 HTTP로 호출하지 않는다. 서버에서 읽을 때는 Core API client 또는 서버 전용 서비스 함수를 직접 사용한다.

## 8. 캐시·데이터 정책

- 상품의 게시 본문과 공개 후기 요약은 캐시할 수 있다.
- 잔여 좌석, hold, 결제, 예약, 개인정보는 공유 캐시하지 않는다.
- 파트너가 상품을 게시·중지하면 `experience:{id}`, 지역, 카테고리 태그를 무효화한다.
- 후기 공개 상태가 바뀌면 후기 요약 태그만 무효화한다.
- 사용자별 데이터는 URL만으로 캐시 키를 만들지 않는다.
- 캐시된 본문과 실시간 회차 조회의 실패를 분리한다.

## 10. 인수 조건

### 10.1 핵심 E2E

1. 비회원이 검색→상세→회차 선택→로그인→hold→테스트 결제→예약 확인을 완료한다.
2. 검색 결과 모달을 닫으면 필터와 스크롤이 보존되고 직접 URL은 전체 페이지로 열린다.
3. 두 고객이 마지막 한 좌석을 동시에 요청할 때 한 명만 hold에 성공한다.
4. 결제 성공 응답이 사라져도 웹훅 뒤 예약 상세에서 확정 상태를 확인한다.
5. 동일 결제·취소 요청을 두 번 보내도 예약·환불이 하나만 생긴다.
6. hold 만료 뒤 결제를 시도하면 새 견적과 좌석 확인을 요구한다.
7. 취소 규정 경계 시각 전후의 예상 환불액이 서버 기준으로 정확히 달라진다.
8. 타인의 예약 URL을 직접 열면 존재 여부를 노출하지 않고 접근이 거부된다.
9. 파트너가 상품을 중지하면 공개 캐시가 무효화되고 신규 hold가 차단된다.
10. 체크인하지 않은 예약은 회차 종료 후에도 후기를 작성할 수 없다.

### 10.2 품질 기준

- 공개 핵심 페이지가 JavaScript 비활성 상태에서도 제목·본문·링크의 기본 정보를 제공한다.
- 결제·예약 화면은 브라우저 뒤로가기와 새로고침에도 중복 거래를 만들지 않는다.
- 모바일 360px, 태블릿, 데스크톱 주요 화면을 지원한다.
- 키보드와 스크린리더로 검색, 로그인, 결제 동의, 취소를 완료할 수 있다.
- 주요 캐시 정책마다 적중, 무효화, 개인정보 혼입 방지 테스트가 있다.

## 11. 단계별 출시

### 1단계 P0

홈, 검색, 상품 상세, 로그인, hold, 결제, 예약 목록·상세, 취소, 후기, 도움말.

### 2단계 P1

지도, 최근 본 상품 병합, 일정 변경 동의, 개인화 추천, 이미지 후기 개선.

### 3단계 P2 학습 확장

- 지역 랜딩 일부를 정적 내보내기와 ISR로 각각 구현해 빌드·갱신 차이를 측정한다.
- 별도 `labs/`에서 Pages Router 호환 페이지 하나를 만들고 App Router와 비교한다.
- 실험 기능은 안정화 여부와 제품상 이점이 확인된 경우에만 격리 적용한다.
