# ADR-0001 아키텍처 결정을 ADR로 기록한다

| 항목 | 내용 |
|---|---|
| 상태 | **유효** |
| 결정일 | 2026-08-24 |
| 관련 문서 | `00 §11.4`, `04 §3`, `06 §2` |
| 관련 ADR | — (최초) |

## 맥락

이 프로젝트는 성공 기준을 "기능을 동작시켰다"가 아니라 **"왜 그렇게 설계했는지 설명할 수 있다"**로 잡았다. 그런데 판단 근거를 담을 저장소가 없었다.

문서 여러 곳이 ADR을 전제하고 있다.

- `00 §11.4` — "기술별 구현 판단을 ADR에 기록하고, 단순 코드량이 아니라 사용자 성능·복잡도·유지보수성을 비교한다"를 **학습 완료 기준**으로 지정
- `06 §2` — "언어는 Java 또는 Kotlin. 착수 시 ADR로 확정한다"
- `04 §3` — "도구 선정은 구현 시작 전 ADR로 고정한다"
- `03 §12`·`04 §13` — "선택한 라이브러리 버전과 브라우저 지원 범위를 잠금 파일과 ADR에 기록한다"

**그럼에도 ADR 실물이 없어, 이미 내린 기술 결정들이 PRD 본문 안으로 흘러들어 갔다.** Core API 언어 결정은 `06 §2.1`에, 영속성 전략은 Advisor 커리큘럼 `§3.5`에 들어가 있다. PRD는 "무엇을 만드는가"를 담는 문서이고 "왜 이 기술로 정했는가"는 다른 문서의 몫인데, 담을 곳이 없어 경계가 무너졌다.

## 결정

`docs/adr/` 아래에 번호를 붙인 마크다운 파일로 아키텍처 결정을 기록한다.

- **형식**: 맥락 / 결정 / 근거 / 결과 네 항목. `_template.md`를 복사해 쓴다.
- **번호**: `NNNN` 4자리 순번. 재사용하지 않는다.
- **파일명**: `NNNN-ascii-slug.md`. 제목은 한국어로 파일 안에 쓰되 **파일명은 ASCII만** 사용한다.
- **불변**: 한 번 쓴 ADR은 고치지 않는다. 생각이 바뀌면 새 ADR을 쓰고 옛 ADR의 상태만 `대체됨(→ ADR-NNNN)`으로 바꾼다.
- **인덱스**: `README.md`에 번호·제목·상태·날짜 표를 유지한다.

문서 간 경계를 다음과 같이 둔다.

| 문서 | 담는 것 |
|---|---|
| PRD `00`~`06`, IA, 결정기록 | 제품 요구 — 화면, 경로, 권한, 상태 전이, 인수조건 |
| **ADR** | 기술 판단 — 언어, 프레임워크, 영속성, 저장소 구조, 라이브러리 |
| 비교 기록 (`03 §9`, `04 §10`) | 두 기술의 차이 — 같은 요구를 각 생태계에서 어떻게 풀었나 |

## 근거

**형식을 네 항목으로 좁힌 이유.** 항목이 많으면 쓰지 않게 된다. 혼자 하는 프로젝트에서 문서 형식의 최대 위험은 부실함이 아니라 **작성 포기**다. 네 항목은 필요한 최소이면서 채울 수 있는 분량이다.

**수정 대신 대체를 택한 이유.** 이 프로젝트의 목적은 결과물이 아니라 학습이다. 판단이 바뀐 이력 자체가 학습 자료이며, 옛 ADR을 덮어쓰면 "그때 내가 무엇을 몰랐는지"가 사라진다. 실제로 Core API 언어는 Kotlin 권고에서 Java로 뒤집혔는데(ADR-0003), 이런 번복이 앞으로도 생긴다.

**파일명을 ASCII로 한 이유.** 다른 문서는 한국어 파일명을 쓰지만, ADR은 코드 저장소 안에 들어가고 커밋 메시지·이슈·CI 로그에서 참조된다. 한국어 파일명은 일부 도구에서 인코딩 문제를 일으킨다. 제목은 한국어를 유지하므로 가독성 손실은 없다.

**검토했으나 탈락한 대안**

| 대안 | 탈락 이유 |
|---|---|
| PRD 안에 결정 근거를 계속 적기 | 이미 그렇게 하다가 경계가 무너졌다. `06 §2.1`이 언어 선택 근거를 네 문단이나 담고 있는데, 이는 "Core API가 무엇을 하는가"를 읽으려는 사람에게 불필요하다 |
| 커밋 메시지로 대체 | 결정 하나가 여러 커밋에 걸치고, 코드가 사라지면 근거도 사라진다. 저장소 구조처럼 코드가 아닌 결정은 담을 곳이 없다 |
| 학습 일지에 함께 쓰기 | 일지는 시간순이라 "이 결정이 지금 유효한가"를 확인할 수 없다. 대체 관계를 표현할 구조도 없다 |

## 결과

- **PRD에서 기술 결정 서술을 점진적으로 걷어낸다.** 당장 `06 §2.1`을 지우지는 않되, 앞으로 기술 판단이 생기면 ADR에 쓰고 PRD에는 참조만 남긴다.
- 후속 결정으로 **ADR-0005 저장소 구조**가 필요하다. ADR 폴더의 최종 위치는 그 결정에 따라간다. 그때까지는 문서 폴더에 둔다.
- 마일스톤 완료 판정에 "해당 구간의 기술 판단이 ADR로 남아 있는가"를 포함한다. `00 §11.4`가 이미 완료 기준으로 지정한 항목이다.
- **번복 조건**: ADR이 20개를 넘고 인덱스만으로 찾기 어려워지면 분류 체계를 다시 본다. 그 전까지는 번호순 단일 목록을 유지한다.
