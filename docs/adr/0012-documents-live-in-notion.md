# ADR-0012 제품 문서의 원본을 Notion에 두고 저장소에는 사본을 두지 않는다

| 항목 | 내용 |
|---|---|
| 상태 | **대체됨(→ ADR-0013)** — 하루 만에 번복했다. 버전 이력의 값을 잘못 계산했다 |
| 결정일 | 2026-08-27 |
| 관련 문서 | Notion `DayLink` 묶음 |
| 관련 ADR | ADR-0013(이 ADR을 대체함), ADR-0001(문서 경계), ADR-0005 |

## 맥락

ADR-0005는 `daylink-shared/docs/`에 PRD·ADR·journal을 전부 두기로 정했다. 2026-08-27에 그 문서 29개를 Notion으로 옮기면서 같은 글이 두 곳에 존재하게 됐다.

두 벌을 유지하려면 동기화가 필요한데, 실측해 보니 대가가 컸다.

- **무손실 통로가 없다.** Notion API에 글을 넣으려면 내용을 도구 호출의 문자열로 다시 타이핑해야 한다. 파일을 그대로 밀어 넣는 경로가 없다. 29개를 한 번 옮기는 동안 **한글 6자가 실제로 깨졌다**(옮→옜, 꾼→꿔, 을→를, 곧→곳, 흐→흘, 춰→췀). 검증에서 잡아 고쳤지만, 자동화하면 이 오류가 규격 문서에 조용히 쌓인다.
- **병합 기준점이 없다.** 같은 날 PRD humanize 검수에서 스테이징 사본과 디스크가 갈라져 3-way 병합으로 복구한 일이 있었다. 자동 동기화가 병합 없이 한쪽을 밀면 그런 편집이 소리 없이 사라진다.
- **동기화 자체가 목적이 아니다.** 동기화가 필요한 이유는 같은 글을 두 벌 갖고 있기 때문이다. 한 벌만 두면 문제가 사라진다.

실무 SI에서도 요구사항은 Confluence·Notion에 있고 저장소에는 코드가 있다. 두 벌 유지가 오히려 현실과 멀다.

## 결정

**PRD와 journal의 원본은 Notion이다.** `docs/prd/`·`docs/journal/`에는 산문 사본을 두지 않고, Notion 링크만 담은 README를 둔다.

**ADR의 원본은 저장소다.** `docs/adr/`는 파일로 남긴다. Notion에 있는 ADR 페이지는 읽기용 사본이며 거기서 고치지 않는다.

**기계가 읽는 산출물의 원본도 저장소다.** `api-spec/`·`fixtures/`·`tokens/`·`e2e/`가 여기 해당한다. 코드 생성기와 테스트가 파일을 직접 읽으므로 Notion에 원본을 둘 수 없다.

## 근거

문서를 어디에 둘지는 **누가 그것을 읽는가**로 갈렸다.

| 문서 | 원본 위치 | 이유 |
|---|---|---|
| PRD·journal | Notion | 사람만 읽는다. 표·필터·모바일 열람이 Notion에서 낫고, 화면 목록 IA는 데이터베이스로 두면 마일스톤별 필터가 된다 |
| ADR | 저장소 | 코드와 함께 버전이 매겨져야 한다. ADR-0001의 "이미 쓴 ADR은 고치지 않는다"를 실제로 보장하는 것은 git 이력이다. 코드 리뷰 중 "이 결정의 근거가 어디지"를 찾을 때도 저장소 안이 빠르다 |
| `api-spec/`·`fixtures/`·`tokens/`·`e2e/` | 저장소 | 기계가 파일을 직접 읽는다. Notion을 원본으로 삼을 수 없다 |

탈락한 대안:

| 대안 | 탈락 사유 |
|---|---|
| 두 벌 유지 + 자동 동기화 | 전사 오류가 규격 문서에 쌓이고 아무도 모른다. 예약 작업은 매번 새 세션으로 뜨고 사용자 컴퓨터가 켜져 있어야 파일에 닿으므로 신뢰성도 낮다 |
| 두 벌 유지 + 변경 감지만 자동 | 사일런트 손상은 없으나 중복 자체가 남는다. 두 벌을 손으로 맞추는 일이 계속 생긴다 |
| 전부 Notion으로 | 규칙은 단순해지지만 ADR 불변성을 Notion 페이지 기록에 기대야 하고, `api-spec/`은 어차피 파일이어야 한다 |
| 전부 저장소에 (현행 유지) | 오늘 옮긴 작업이 헛일이 되고, 화면 목록 IA를 데이터베이스로 다루는 이점을 잃는다 |

## 결과

- **ADR-0005의 문서 위치 부분이 대체된다.** 저장소 6개 분리, GitHub Packages 배포, SemVer 규약, 로컬 포트 규약은 그대로 유효하다. ADR-0005 본문은 ADR-0001 규칙에 따라 고치지 않는다.
- **저장소만 클론한 사람은 제품 요구를 볼 수 없다.** `docs/prd/README.md`의 링크를 따라가야 한다. 혼자 하는 프로젝트라 지금은 비용이 아니지만, 협업자가 생기면 Notion 접근 권한이 선행 조건이 된다.
- **오프라인에서 PRD를 못 읽는다.** 이동 중 참조가 필요하면 Notion 앱의 오프라인 저장을 쓴다.
- **PRD는 git 이력에서 빠진다.** 대신 Notion 페이지 기록이 그 역할을 한다. `docs/prd/archive/`의 대체된 문서는 git 이전의 유일한 기록이므로 저장소에 남긴다.
- **`00 §N.N` 같은 상호참조 표기는 그대로 쓴다.** 문서 번호가 식별자 역할을 계속하므로 Notion으로 옮겨도 참조가 깨지지 않는다.
- **번복 조건**: ① 협업자가 늘어 Notion 접근 권한 관리가 부담이 되면 재검토한다 ② PRD를 코드와 함께 리뷰해야 할 일이 반복되면(예: PR에서 요구사항 변경을 같이 봐야 함) 저장소 복귀를 검토한다 ③ Notion에서 규격 문서의 표·코드블록이 깨지는 일이 반복되면 재검토한다.
