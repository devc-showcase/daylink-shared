# ADR-0014 회차의 영어 식별자를 `Slot`으로 한다

| 항목 | 내용 |
|---|---|
| 상태 | **유효** |
| 결정일 | 2026-08-31 |
| 관련 문서 | `00 §5.1`, `00 §7.2`, `06 §4`, `06 §8.6` |
| 관련 ADR | ADR-0011(명명 판단의 선례) |

## 맥락

`06 §4` 도메인 모델이 회차 엔터티를 `Session`으로 정의했다. 같은 문서 `06 §8.6`은 "이미 발급된 세션이 만료 이후에도 통과하면 안 된다"에서 **인증 세션**을 가리킨다. 한 문서 안에서 같은 단어가 두 뜻으로 쓰였다.

`api-spec/design-checklist.md`의 마지막 확인 항목이 "같은 개념에 다른 이름을 쓴 곳이 없는가"를 묻는데, 이건 그 반대 경우다 — **다른 개념에 같은 이름**을 썼다.

Core API는 Java 21 + Spring Boot 4다(ADR-0002·0003). 이 환경에서 도메인 타입 `Session`과 서블릿의 `HttpSession`이 한 파일에 들어오면 자동완성과 import 목록에서 구분이 어렵다. 계약이 네 프론트 구현에 타입으로 생성되므로 이름은 한 번 굳으면 바꾸기 비싸다.

코드가 아직 없고 명세만 있는 시점이다. 바꾸려면 지금이 가장 싸다.

## 결정

**회차의 영어 식별자를 `Slot`으로 개명한다.** 한국어 "회차"는 그대로 둔다.

| 자리 | 전 | 후 |
|---|---|---|
| 엔터티 | `Session` | `Slot` |
| 식별자 필드 | `sessionId` | `slotId` |
| 경로 | `/sessions/{sessionId}` | `/slots/{slotId}` |
| 화면 경로 | `/partner/sessions`, `/desk/sessions/{id}` | `/partner/slots`, `/desk/slots/{id}` |
| 스냅숏 필드 | `sessionStartAt` | `slotStartAt` |
| 오류 코드 | `SESSION_NOT_BOOKABLE`, `CHECKIN_SESSION_MISMATCH` | `SLOT_NOT_BOOKABLE`, `CHECKIN_SLOT_MISMATCH` |
| 분석 이벤트 | `select_session` | `select_slot` |

`00 §5.1`에 용어 정의를 신설해 `Slot`이 이 프로젝트에서 뜻하는 바와 뜻하지 않는 바를 적었다. `06`의 인증 세션 언급에는 "인증 세션"이라고 명시했다.

## 근거

`Slot`은 예약 도메인에서 널리 쓰여 국내 실무자도 바로 읽는다. 짧아서 URL과 코드가 깔끔하다. Java·Spring에 같은 이름의 표준 타입이 없다.

검토했으나 탈락한 대안이다.

| 후보 | 탈락 사유 |
|---|---|
| `Session` 유지 | 이 ADR이 존재하는 이유다. `HttpSession`과 겹친다 |
| `Occurrence` | 의미는 가장 정확하다. `02 §6`의 "단일 회차·반복 회차"가 RFC 5545의 recurring occurrence와 정확히 맞고 충돌도 없다. 그러나 `/partner/occurrences/{id}`처럼 URL과 식별자가 길어진다. **사용자가 간결함을 우선해 탈락시켰다** |
| `TimeSlot` | 아래 "감수하는 것"의 Vue 충돌을 피할 수 있었다. 그러나 회차는 시간과 장소를 함께 묶는 단위라 시간만 강조하는 이름이 절반만 맞고, `Slot`보다 길다. **사용자 판단으로 탈락** |
| `Event` | `06 §4`에 이미 `CheckInEvent`가 있고 도메인 이벤트와도 겹친다 |
| `Departure` | 투어 업계 용어다. 도자기 원데이 클래스에 쓰면 어색하다 |
| `Schedule` | 일정 **모음**을 연상시킨다. 회차는 낱개다 |

## 결과

**감수하는 것 — Vue의 `<slot>`과 겹친다.** `04 §Vue`가 컴포넌트 슬롯을 다루므로 Admin Vue 구현에서 도메인 타입 `Slot`과 템플릿의 `<slot>`이 같은 파일에 들어온다. Vue 3는 현재 학습 대상이라 혼동 비용이 더 크다.

완화책으로 `00 §5.1`에 규약을 뒀다 — **`.vue` 안에서 도메인 값을 담는 변수·prop 이름으로 `slot`을 쓰지 않고 `timeSlot` 같은 이름을 쓴다.** 타입 이름 `Slot`은 그대로 쓴다. 템플릿 문법과 타입은 문법 위치가 달라 사람은 구분할 수 있다는 판단이다.

**두 번째로 감수하는 것 — "슬롯 하나 = 좌석 하나"로 읽힐 여지.** 이 프로젝트의 `Slot`은 정원 1~N명을 담는 그릇이다. `00 §5.1`이 이를 명시한다.

**함께 바뀐 문서.** `00`(용어 신설) · `01`(분석 이벤트) · `02`(화면 경로 5개) · `06`(엔터티·인증 세션 표기) · `api-spec/openapi.yaml` · `api-spec/errors.md` · `api-spec/design-checklist.md` · IA v2.3 xlsx 5개 셀.

**번복 조건.** Vue 구현에서 `slot` 혼동으로 실제 결함이 한 번이라도 나오면 `TimeSlot`으로 다시 본다. 그때는 코드가 이미 있으므로 개명 비용이 지금보다 크다는 점을 함께 계산한다.
