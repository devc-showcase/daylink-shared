# ADR-0006 명시적 SQL 도구로 MyBatis를 쓴다

| 항목 | 내용 |
|---|---|
| 상태 | **유효** |
| 결정일 | 2026-08-24 |
| 관련 문서 | `06 §8.1`, `06 §8.6`, `06 §12` |
| 관련 ADR | ADR-0004(영속성 전략)가 미결로 남긴 항목, ADR-0009(빌드·테스트) |

## 맥락

ADR-0004가 "M1~M3 전반은 명시적 SQL"로 정하면서 **도구 택일은 미결로 남겼다.** 후보는 Spring JDBC(`JdbcClient`)와 MyBatis 둘이었다.

`06 §8.1`이 요구하는 것은 다음이다.

> `SELECT`로 잔여를 읽고 애플리케이션에서 비교한 뒤 `UPDATE` 하는 방식은 금지한다. 조건부 갱신, 행 잠금, 또는 제약 조건 중 하나로 **데이터베이스가 판정하게 한다.**

즉 도구의 조건은 "SQL을 감추지 않을 것"이다. 두 후보 모두 이 조건은 만족한다. 판단은 다른 축에서 갈렸다.

학습자의 영속성 경험은 0이고, 프로젝트 목적은 학습 1순위·SI 실무 적용 2순위다.

## 결정

**MyBatis를 쓴다.** SQL은 XML 매퍼에 둔다.

M3 후반에 JPA를 낙관적 락에 한정해 도입할 때(ADR-0004), MyBatis와 JPA의 담당 경계를 그 시점에 별도 ADR로 기록한다.

## 근거

**2순위 목적이 결정했다.** 국내 SI 현장에서 MyBatis 사용률이 압도적이다. 여기서 익힌 매퍼 구조·동적 SQL·결과 매핑이 상주 현장 코드를 읽고 고치는 데 그대로 쓰인다. 순수 학습 효율만 따지면 Spring JDBC가 유리하지만, ADR-0003에서 Java를 택할 때와 **같은 기준**으로 판단했다 — 학습 경량화보다 현장 전이 가치를 앞에 둔다.

**부수 이점이 하나 있다.** XML 매퍼는 SQL을 한곳에 모아 놓으므로, `06 §8.1`이 요구하는 락과 조건이 **파일 하나에서 전수 검토된다.** "이 프로젝트에서 `FOR UPDATE`가 걸린 쿼리가 몇 개인가"를 매퍼 파일만 열어 확인할 수 있다. `06 §12`가 지적한 "잘못된 설계가 테스트를 통과하며 살아남는" 구조에 대한 시각적 방어선이 된다.

**MyBatis가 SQL을 대신 만들어 주지 않는 점도 이 프로젝트에서는 장점이다.** PostgreSQL의 `FOR UPDATE`·`SKIP LOCKED`·조건부 `UPDATE`를 직접 써야 하므로, 락을 "건 것"과 "걸었다고 생각한 것"이 갈라지지 않는다.

**검토했으나 탈락한 대안**

| 대안 | 탈락 이유 |
|---|---|
| Spring JDBC (`JdbcClient`) | Spring 내장이라 학습 축이 늘지 않고, Java 21 텍스트 블록으로 SQL 가독성도 확보된다. 무엇보다 **락과 트랜잭션 경계가 같은 Java 파일 안에 나란히 보인다.** 순수 학습만 보면 이쪽이 낫다. 그러나 SI 레거시 코드 읽기 전이가 약해 2순위 목적에 기여하지 않는다 |
| 구간별 분리 (쓰기는 JdbcClient, 조회는 MyBatis) | 둘 다 경험하고 각각의 강점을 쓸 수 있다. 그러나 한 프로젝트에 영속성 접근이 둘 공존하면 경계 규칙을 따로 정해야 하고, M3 후반 JPA까지 들어오면 셋이 된다. 백엔드 제로 베이스에서 감당할 복잡도가 아니다 |
| JOOQ | 타입 안전과 가시성을 모두 갖지만 국내 SI 사용률이 낮아 2순위 목적에 기여하지 않고, 학습 축만 하나 늘어난다 (ADR-0004에서 이미 기각) |

## 결과

- **학습 축이 하나 늘어난다.** Spring 위에 MyBatis 설정·매퍼 규약·결과 매핑을 더 배워야 한다. ADR-0003의 Java 선택(+15h)에 이어 2순위 목적을 위해 지불하는 두 번째 비용이다.
- **가장 큰 위험: SQL이 Java 코드 밖에 있다.** `@Transactional`이 걸린 서비스 메서드와 실제 락을 거는 SQL이 서로 다른 파일에 있으므로, **트랜잭션 경계와 락을 동시에 따라가는 훈련이 한 단계 어려워진다.** 이 프로젝트의 핵심 학습이 바로 그 지점이다.
  - **완화**: 락이 걸린 쿼리에는 XML 주석으로 ① 어느 트랜잭션 경계 안에서 호출되는지 ② 어떤 격리 수준에서 안전한지를 함께 적는다. ADR-0004의 "각 동시성 방어의 안전 근거를 격리 수준과 함께 ADR에 적는다"를 매퍼 파일 수준으로 내린 규칙이다.
- **ADR-0003이 남긴 체크 예외 위험과 겹친다.** 롤백 규칙(ADR-0007 예정)을 정할 때 MyBatis가 던지는 예외 유형을 함께 확인해야 한다.
- **번복 조건**: M1~M2에서 매퍼 XML과 트랜잭션 경계를 오가는 비용이 실제로 진도를 막고, 위 완화책으로도 `06 §8.1` 검증이 어려우면 `JdbcClient`로 전환한다. 반대로 XML 매퍼가 SQL 전수 검토에 실제로 도움이 되었다면 이 판단을 M3 회고에 근거로 남긴다.
