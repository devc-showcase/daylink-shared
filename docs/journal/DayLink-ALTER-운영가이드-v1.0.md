## 0. 이 가이드의 전제

DayLink는 이미 ALTER 산출물의 상당 부분을 갖고 있다.

| ALTER 역할 | 이미 존재하는 대응물 |
|---|---|
| Advisor | PRD 00 §11 학습 완료 기준, 03 §8 / 04 §9 권장 구현 순서 |
| Librarian | 03 §12, 04 §13 공식 문서 URL 고정 + PRD 6종 자체가 1차 소스 |
| Editor | 인수조건 30개(B2C-AC-01~14, ADM-AC-01~16), 05 §8.3 동등성 실패 판정 |
| Tutor | 03 §6 / 04 §6 각 절의 "비교 질문" |
| Roommate | 05 서비스플로우 검증 문서 (결함 16건 발견 = 교차 관점 1회 수행 결과) |

따라서 ALTER는 **백지에서 커리큘럼을 짜는 도구가 아니라, 이미 있는 계획의 빈칸을 메우는 도구**로 운영한다.

### 규모 실측

| 항목 | 수량 |
|---|---:|
| B2C 28화면 × 2구현(Next·Nuxt) | 56 |
| Admin 56화면 × 2구현(React·Vue) | 112 |
| 총 화면 구현 | **168** |
| 완료 조건 | 59 (B2C-AC 14 · ADM-AC 16 · CORE-AC 29) |
| E2E 시나리오 × 4구현 | 72 |
| Core API (실무 레벨) | 명세 11 엔드포인트 · CORE-AC 29 |

주 20시간 = 연 약 1,000시간. 화면당 4시간 × 168 = 672시간, 백엔드 300시간을 더하면 여유가 거의 없다.
**Vue 3·Nuxt 4 학습 곡선은 아직 포함되지 않은 숫자다.**

## 1. 역할 우선순위

### 상시 운영 (2개)

**Tutor — 1순위**
- Vue 2 → Vue 3: 반응성 구현(`Object.defineProperty` → `Proxy`), Composition API·`<script setup>`, Teleport·Fragment, Vuex → Pinia
- Nuxt 2 → Nuxt 4: Nitro 서버 엔진, `asyncData`/`fetch` → `useFetch`/`useAsyncData`, route rules 하이브리드 렌더링, 오토 임포트, Webpack → Vite
- 진짜 위험은 "모른다"가 아니라 **"안다고 착각한다"**(negative transfer). 완전 초보보다 위험하며 강의로는 안 잡힌다.
- 2순위 대상: Core API 동시성(원자적 재고 확보, 멱등 키, 불변 원장). 프론트 경력이 길수록 직관이 틀리기 쉬운 영역.

**Editor — 2순위**
- 목적이 "학습 + 실무 적용"이므로 지적 기준이 코드 품질 → "팀원이 인수 가능한가", "SI 검수를 통과하는가"까지 확장
- AI가 짠 코드를 내가 검수하는 훈련 자체가 실무 역량

### 지정 시점 투입 (3개)

**Advisor — 용도를 바꿔서 사용**
- 새 커리큘럼 설계가 아니라 **범위 절단**이 목적
- 5가지 산출물 중 이 프로젝트에서 결정적인 것은 **"지금 무시할 것"**

**Librarian — 초기 1회 + 백엔드 착수 시 1회**
- 프론트 소스는 이미 고정됨. 새로 선별할 것은 백엔드 영역(동시성 제어, 멱등성 설계, 불변 원장 패턴)뿐

**Roommate — 마일스톤 종료 시 스팟 투입**
- 이 프로젝트는 교차 관점이 이미 내장(예약·결제·정산·감사·오프라인 동기화는 이미 분야 밖)
- 유효한 투입 각도: 정산·회계 관점 / 개인정보·보안 감사 관점 / 비개발자 현장 운영자 관점

## 3. 위험 체크리스트

### 최대 함정
**PRD가 너무 정밀해서 AI에게 그대로 던지면 코드가 나온다.** 인수조건까지 적혀 있으므로 AI가 통과하는 코드를 만들어낸다. 168화면이 완성되는데 배운 것은 없는 상태가 된다.

### 방지 장치 3개

- [ ] **"먼저 답하고 나서 묻기"** — 어떤 질문이든 AI에게 던지기 전에 내 답을 3줄로 먼저 적고, 그다음 AI 답과 대조한다. 이것이 인출 연습이며, "읽어서 아는 것"과 "꺼내 쓸 수 있는 것"을 가른다.
- [ ] **두 번째 구현에 AI 코드 생성 금지** — Nuxt·Vue 구현은 첫 구현(Next·React) 코드를 AI에게 보여주지 않고 PRD만 보고 시작한다. 보여주면 번역 작업이 되고 04 §9가 경고하는 "기억 의존 작업"이 된다.
- [ ] **커밋 게이트** — 기능 묶음 커밋 전에 03 §6 / 04 §6 비교 질문에 문서 없이 답하고 Tutor에게 채점받는다. 답을 못 하면 코드가 돌아가도 커밋하지 않는다.

### 개별 함정

- [ ] **Vue 2 negative transfer** — AI는 Vue 3 코드를 주는데 Vue 2 멘탈 모델로 읽으면 이해했다고 착각한다. Tutor에게 반드시 요구할 것: *"Vue 2에서는 어떻게 했고 Vue 3에서 왜 바뀌었는지를 묻는 질문을 해라."* 차이 기반 질문이 아니면 안 잡힌다.
- [ ] **Editor 지적을 AI에게 고치게 하기** — ALTER 정의상 수정은 본인 몫. 편해서 어기기 쉽고, 어기면 학습 효과 0.
- [ ] **Advisor 계획이 PRD와 충돌** — PRD가 상위 문서임을 프롬프트에 명시할 것.
- [ ] **고정 소스의 노후화** — Nuxt 4·Vue 3는 변화가 빠르다. 03 §12 마지막 문장의 경고(구현 시작 시 재확인, 잠금 파일 고정)를 실제로 지킬 것.
- [ ] **동등성 비교의 자기기만** — 한쪽만 잘 만들고 "프레임워크 한계"로 결론짓는 것. 05 §8.3이 이미 경고하는 항목.

## 프로젝트 사실
- 이름: DayLink — 지역 클래스·체험 예약 플랫폼 (학습용 가상 서비스)
- 제품 2개: B2C 1개, Admin 1개
- 구현 4벌: B2C를 Next.js와 Nuxt로 각각, Admin을 React SPA와 Vue SPA로 각각
- 화면 수: B2C 27, Admin 52 (공통 9 / 파트너 15 / 현장 8 / 플랫폼 20)
- 실제 구현량: 28×2 + 56×2 = 168화면
- 인수조건 30개, 대표 E2E 시나리오 18개(각 4벌 실행 = 72회)
- Core API: 내가 직접 실무 레벨로 만든다. PRD 00 §8이 요구하는 항목은
  원자적 재고 임시확보, 멱등 요청 처리, 예약·결제·환불·정산 상태 전이,
  불변 원장과 조정 항목, 감사 로그, 오프라인 체크인 충돌 판정이다.
- IA 확인필요 7건은 2026-08-24 재인터뷰로 전부 확정됐다(`docs/prd/DayLink-확인필요-7건-결정기록-v2.0.md`). IA v2.3이 그 결과다.

## 내 현재 수준 (정확히 이대로 반영하라)
- React SPA: 실무 유지보수 경험 있음
- Next.js: 실무 경험 있음 (라우터는 [App Router / Pages Router / 둘 다] 기준)
- Vue: **Vue 2만 실무 경험. Vue 3는 미경험**
- Nuxt: **Vue 2 기반 Nuxt 2만 실무 경험. Nuxt 3/4는 미경험**
- 백엔드: [여기에 본인 수준을 적을 것 — 예: Node/Express API 작성 경험은 있으나
  동시성 제어·트랜잭션 격리 수준·이벤트 아웃박스는 설계해 본 적 없음]
- 직군: JavaScript/TypeScript 주력, SI 업계 프리랜서

이 수준 정보에서 가장 중요한 점은 **학습 부담이 대칭이 아니라는 것**이다.
React/Next 쪽은 심화·비교 학습이지만, Vue 3/Nuxt 4 쪽은 사실상 새 기술 학습이다.
게다가 Vue 2 경험이 Vue 3 이해를 방해하는 negative transfer 위험이 있다.
커리큘럼은 이 비대칭을 반드시 반영해야 한다.

## 시간 조건
- 주 20시간 이상 투입 가능 (연 약 1,000시간)
- 마감일은 없지만, 완주하지 못하면 실패로 본다

## 목적
학습이 1순위, SI 실무 적용이 2순위다. 포트폴리오 공개도 열어둔다.
"기능을 동작시켰다"가 아니라 "왜 그렇게 설계했는지 설명할 수 있다"가 성공 기준이다.

## 요구 산출물 — 아래 5가지를 순서대로, 각각 표로 제시하라

1. **목적지**
   1,000시간 뒤 내가 무엇을 할 수 있어야 하는지를 검증 가능한 문장으로 정의하라.
   "Nuxt를 안다" 같은 문장은 금지. "무엇을 보고 무엇을 판단할 수 있다"로 쓰라.

2. **현재 수준 진단**
   네 기술 + 백엔드 각각에 대해 (a) 이미 가진 것, (b) 없는 것,
   (c) **잘못 알고 있을 가능성이 높은 것**을 구분하라.
   (c)는 Vue 2 → 3, Nuxt 2 → 4 구간에서 특히 구체적으로 지목하라.

3. **학습 순서**
   PRD 03 §8과 04 §9에 권장 구현 순서가 이미 있다.
   그 순서를 그대로 쓸지, 내 비대칭 수준 때문에 바꿔야 하는지 판단하고 근거를 대라.
   Core API를 어느 시점에 넣을지도 함께 정하라.

4. **지금 무시할 것** ← 이 항목이 가장 중요하다
   1,000시간 안에 168화면 + 실무 레벨 백엔드는 들어가지 않을 가능성이 높다.
   구체적으로 무엇을 버리거나 미룰지 목록으로 제시하고, 각 항목마다
   (a) 왜 버려도 학습 목표가 유지되는지, (b) 버리면 잃는 것은 무엇인지를 적어라.
   화면 단위, 인수조건 단위, 구현 벌 수 단위 중 어디를 자르는 것이 손실이 적은지 판단하라.

5. **마일스톤 5개**
   각 마일스톤마다 다음을 명시하라.
   - 완료 판정 기준 (PRD 인수조건 ID로 지정)
   - 예상 소요 시간 (주 20시간 기준 몇 주인지)
   - 이 마일스톤에서 배우는 것 한 문장
   - 중도 포기 위험이 가장 높은 지점과 그 대비책
