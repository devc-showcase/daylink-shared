# fixtures

시드 데이터와 테스트 계정. **다섯 저장소가 모두 쓴다.**

`00 §11.3`이 "같은 API 명세 준수 테스트와 핵심 E2E 시나리오를 네 구현이 공유한다"를, `05 §4.2`가 "같은 테스트는 동일 시드의 별도 테넌트에서 실행한다"를 요구한다.

## 담을 것

- 역할별 테스트 계정 — `02 §3.1`의 여덟 역할 + `READ_ONLY_AUDITOR` 한시 부여 사례
- 상품·회차·재고 시드 — 마지막 1좌석 경쟁(`CORE-AC-01`)을 재현할 수 있는 상태 포함
- 예약·결제·환불·정산 원장 시드
- 경계 시각 시드 — 취소 정책 경계(`00 §6.4`) 앞뒤를 시험할 수 있는 데이터

## 규칙

- **구현별 테넌트를 분리한다.** 쓰기 흐름 비교는 각 구현 전용 데이터 세트를 쓰고 종료 후 초기화한다(`05 §4.2`).
- 실제 개인정보를 넣지 않는다.
